
## TRD: Technical requirements

One Laravel 13 app, one Filament 5 panel for all four roles, MySQL for data, Redis for queues and cache, Horizon under Supervisor. No separate SPA, no API in v1.

### Architecture

- **One panel, scoped by policy.** Every resource has a policy generated by Shield; Eloquent global scopes restrict employees to own records. Never rely on hiding a button.
- **Domain actions, not fat resources.** Business rules live in `app/Actions` (e.g. `SubmitLeaveRequest`, `ApproveLeaveRequest`, `LogTime`, `LockMonth`). Filament forms call actions; tests call actions directly.
- **Value objects** for `Money` (minor units + currency) and `LeaveDuration` (days, half-day aware).
- **Enums** (PHP backed) for statuses, project type, leave half (AM/PM), employment type.
- **Events → listeners → queued notifications** for leave and assignment.

### Business rules

1. **Leave days** = working days in range (country workweek) − country holidays, with half days at either end counting 0.5. Computed by one service, tested against fixtures.
2. **Annual grant**: scheduled job on 1 Jan writes one ledger row per user per leave type; new joiners get a prorated row on `start_date`.
3. **Approval** writes a negative ledger row; cancellation of an approved request writes the reversing positive row. Never edit ledger rows.
4. **Rate snapshot**: on save, a time entry copies the client rate effective on its date. Rate changes never touch existing entries.
5. **Logging guards**: date ≤ today, month not locked, project active, task not closed, task's project equals entry's project, total ≤ max hours/day setting (warn at 10 h, block at 16 h).
6. **Direct project logging** allowed only when `can_log_directly`; technology then chosen from the project's list.

### Security and privacy

- MFA required for superadmin and admin (Filament's built-in MFA).
- Private profile and salary data load only through their own relation managers, behind policies, so they never enter an employee's Livewire payload.
- Impersonation and every salary, rate or lock change are activity-logged with actor.
- Backups encrypted, retained 30 days, restore tested once per quarter.
- &#91;LIKELY\] Personal data processing must follow Albania's personal data protection law; get a lawyer to confirm retention periods for ex-employee HR data.

### Operations

- Supervisor runs Horizon; cron runs `schedule:run` every minute.
- Scheduled: yearly leave grant, nightly backup, daily "no time logged yesterday" reminder, monthly lock reminder.
- Error tracking via Sentry or Flare; health check endpoint for uptime monitoring.

### Testing

- Pest feature tests per action and per policy (each role × each ability).
- Fixture-based tests for leave counting across weekends, holidays, half days, year boundaries.
- Filament resource tests for create/edit forms and table filters.
- Target: every action and policy covered; Larastan level 6 clean.

## Build guide: TODO list with Claude

Build in 12 vertical slices with Claude Code, one slice per session, tests before code, and a human review before every merge. Asking Claude for "the whole app" in one prompt produces a demo that falls apart at leave counting and permissions.

**The biggest Claude-specific risk:** \[LIKELY\] Claude's training data has far more Filament 3 than Filament 5 code, so it will write old namespaces (`Forms\Components` instead of schemas). Laravel Boost's version-aware docs plus an explicit rule in CLAUDE.md are the fix; check the first resource it writes line by line.

### One-time setup

- [ ] Install Claude Code (CLI or the Code tab in Claude Desktop) and open it in an empty folder.
- [ ] Export this doc as Markdown into the repo as `docs/PRD.md` and `docs/TRD.md`.
- [ ] `composer create-project laravel/laravel task-logger` (Laravel 13), then `composer require laravel/boost --dev && php artisan boost:install` and choose Claude Code.
- [ ] Append the project rules below to the generated `CLAUDE.md`.
- [ ] Create the GitHub repo and a CI workflow (Pest, Larastan, Pint) before writing any feature.

Project rules to append to CLAUDE.md:

```markdown
# task-logger rules
- Spec: docs/PRD.md and docs/TRD.md. If code and spec disagree, stop and ask.
- Laravel 13, Filament 5, Livewire 4, PHP 8.4. Use Boost docs search before writing Filament code. Never use Filament 3 APIs.
- Business logic lives in app/Actions; Filament resources only call actions.
- Money = integer minor units + currency. Time = minutes. Never floats.
- Every model gets a policy. Every action and policy gets Pest tests written first.
- Never edit leave_ledger or salaries rows; insert corrections.
- Run `composer test`, `vendor/bin/phpstan`, `vendor/bin/pint` before saying a task is done.
- One ticket per branch. Don't touch files outside the ticket's scope.
```

### Working loop per slice

1. **Plan mode**: paste the slice prompt below; Claude proposes files, migrations and tests. You correct the plan, not the code.
2. **Tickets**: if your skills plugin is installed in Claude Code, run `/to-tickets` on the plan; otherwise ask for a numbered ticket list.
3. **Build test-first**: `/tdd` per ticket (red, green, refactor).
4. **Review**: `/code-review` against the spec, then read the diff yourself. Merge only green CI.
5. **Clear context** before the next slice; CLAUDE.md and docs carry the memory, not the chat.
