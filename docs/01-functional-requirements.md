# 01 — Functional requirements

Numbered FR-xx, grouped by module. Each links to business rules (BR), workflows (W), permissions (SPEC §4.4) and has acceptance criteria (AC) in Given/When/Then form. Tags per SPEC §0.1. Permission names are `resource.action`; code checks permissions via Policies, never role names.

## 1. Identity and access

**FR-01 Create users (W-01).** Perm `employees.create`. Only superadmin creates users; no self-registration.
- AC: Given a guest, when they visit any registration URL, then 404. Given superadmin, when creating a user with role, department, country, manager, position, employment type, start date, then the user exists, receives a set-password email `[ASSUMED]`, and an activity log row is written (BR-32).
- AC: exactly one role is assigned (D-09); assigning two is rejected.

**FR-02 Permission-first RBAC.** Permissions and roles come from a seeder derived from SPEC §4.4. Superadmin holds every permission explicitly (no `Gate::before`).
- AC: grep of `app/` finds no `hasRole(` / `role:` checks for authorisation. A test iterates the grid and asserts each role's permission set equals the seeded set.

**FR-03 Deactivate / ban.** Perm `employees.deactivate` (superadmin). Uses `cybercog/laravel-ban` (D-20).
- AC: banned user cannot log in; history is retained.

**FR-04 Impersonation `[OPTIONAL]`.** Perm `employees.impersonate`, superadmin only, activity-logged.

## 2. Master data (M1)

**FR-05 Countries (W-01 step 1).** Perm `countries.manage`; assistant has create-only (`add`). Fields: name, code, prefix, timezone, currency_code, working_days (default Mon–Fri).
- AC: duplicate `code` rejected. Assistant can create but not update/delete.

**FR-06 Country leave policies (BR-18).** Perm `country_leave_policies.manage`. Per country and leave type with `effective_from`.
- AC: given two policies with different `effective_from`, the active one for a date is the latest on or before it. Unique (country, type, effective_from).

**FR-07 Departments, technologies, labels, payment plans.** Perms `departments.manage`, `technologies.manage` (assistant `add`), `labels.manage` (superadmin), `payment_plans.manage` (superadmin).
- AC: technology `name` unique. Department slug generated by sluggable. Seeded labels and leave types exist after `db:seed`.

**FR-08 Bank holidays (BR-25, W-07).** Perm `bank_holidays.manage` (superadmin, hr); `bank_holidays.view` for all.
- AC: `end_date >= start_date` enforced. A holiday on a weekend does not auto-shift (D-08). HR can create the observed Monday as a separate entry.

**FR-09 Settings.** Perm `settings.manage` (superadmin, admin, hr). Settings: `anonymize_after_months` (default 2), carry-over toggle default off.

## 3. People (M2)

**FR-10 Directory (BR-26).** Perm `employees.view_directory`. Shows name, surname, position, department, skills, avatar only.
- AC: for a user without `employees.view_hr_record`, no query, resource, export or response contains any private field (email, phone, DOB, gender, address, education, marital status, emergency contacts, source of hire, health insurance, employment type, start date, manager, country, description, metadata).

**FR-11 HR record.** Perms `employees.view_hr_record`, `employees.update_hr_record` (superadmin, admin, hr; ADR-0009). Phones stored E.164.
- AC: employee role gets 403 on another's HR record. Employee viewing their own record: **denied by default** (D-14 open).

**FR-12 Skills with level.** `technology_user.level` 1–10, unique per user/technology.

**FR-13 Emergency contacts.** Many per user, phone E.164.

**FR-14 Salaries (BR-29).** Perm `salaries.view/manage` (superadmin, admin, hr). Append-only.
- AC: update/delete of a salary row is refused; changing salary creates a new row, prior `active` becomes `superseded` `[ASSUMED D-19]`. Current = latest `active` with `effective_date <= today`.

**FR-15 Performance reviews (W-09, BR-27).** Create: `performances.create` (superadmin, admin). View: `performances.view` (superadmin, hr, plus direct manager via policy; D-21, ADR-0007).
- AC: admin who is not the manager can create but gets 403 reading. Score 1–10.

**FR-16 Offboarding (W-10, BR-28).** Perm `offboardings.view/manage` (superadmin, admin, hr). At most one non-cancelled per user.
- AC: completing sets login deactivated (ADR-0008). Two months after `end_date` the anonymisation job replaces name, email, clears profile/contacts/avatar/metadata, scrubs activity-log properties, sets `anonymized_at`; logs, leave, salary, performance rows remain.

## 4. Clients and projects (M3)

**FR-17 Customers (W-02).** Perms `clients.view`, `clients.create/update/activate/deactivate`. Currency defaults from country; immutable once rates or logs exist (D-18). Priority on customer only (D-02).
- AC: deactivated customer cannot get new projects/tasks/logs (BR-31).

**FR-18 Client technology rates.** Rows (customer, technology, rate_minor, effective_from). Perm `clients.view_rates` (superadmin, admin).
- AC: rate for a date = latest `effective_from` on or before. Users without `clients.view_rates` never receive rate, payment plan or budget fields in screens or exports.

**FR-19 Projects.** Perms `projects.view/create/update/delete/change_status/manage_members`. Manager must hold role admin (BR-30).
- AC: choosing a technology not in the client's rate list is rejected (BR-10). Changing a manager's role away from admin while they manage a project is rejected.

**FR-20 Budget (BR-13, BR-14, D-04).** `estimated_hours = Σ project_technology.estimated_hours`; `budget_minor = Σ(hours × client rate at project start_date) + Σ fixed costs`, recomputed on change of technologies, estimates, rates, fixed costs.
- AC: fixed cost in a currency different from the client's is rejected. Unit test with two technologies and two fixed costs yields the exact integer.

**FR-21 Fixed costs.** Perm `fixed_costs.manage` (superadmin). `date` normalised to first day of month.

**FR-22 Tasks (W-03).** Perms `tasks.view_any/view_own/create/update/delete/assign`. One nullable assignee. Technology in project's technologies (BR-10). Parent in same project, no cycles (BR-11).
- AC: cycle (A→B→A) rejected. Parent in another project rejected.

**FR-23 Task status (BR-35).** Assignee (`tasks.change_status_own`), creator for tasks created for others, admin/superadmin (`tasks.change_status`).
- AC: employee changing status of another's task → 403.

## 5. Time logging (M4)

**FR-24 Create log (W-03, W-04, BR-02..06, D-11).** Explicit work `date`; backdating allowed until the month is locked (D-11, open).
- AC (task log): task must be assigned to the user; project and technology copied from task.
- AC (direct log): `task_id` null; project `can_log_directly_to_project`; user in `project_user`; technology in project technologies.
- AC: duration > 0, minutes 0–59, stored as `duration_minutes`; user daily total ≤ 1440 minutes (BR-04). `log_type` in the four values (BR-05).
- AC: `rate_minor`/`rate_currency` snapshot from the rate effective on log date; no rate → creation blocked with message (BR-06). Later rate changes do not alter it.

**FR-25 My Day (BR-03, BR-08).** Direct-logging checkbox swaps the list: own tasks vs eligible projects. Tasks with `force_to_log` pinned until completed/cancelled.
- AC: pinned task disappears when its status is completed or cancelled.

**FR-26 Edit/delete log.** `logs.update_own/delete_own` for own logs; `logs.view_any` for lists.

**FR-27 Month lock (BR-07, W-08).** Perm `timesheets.lock` (superadmin). Unlock logged.
- AC: employee create/edit/delete in a locked month → denied. Admin/superadmin (`logs.edit_locked`) can; activity log stores before/after.

**FR-28 Exports (BR-33).** `logs.export` (superadmin, assistant); `projects.export`, `clients.export`, `tasks.export` (assistant, and superadmin). Queued; rate columns omitted unless `clients.view_rates`.
- AC: assistant export contains no rate/budget/payment-plan column.

## 6. Leave (M5)

**FR-29 Request leave (W-05, BR-16, 17, 23, 24).** `leave_requests.create_own`. `days_requested` computed server-side: working days only, skipping the country's non-working weekdays and the employee's country bank holidays; half days 0.5.
- AC: Mon–Fri request spanning a Wednesday holiday = 4.0. Weekend holiday changes nothing. Overlap with pending/approved request rejected. Over balance (balance minus pending) rejected for balance-affecting types.

**FR-30 Two-stage approval (D-07, BR-20, 21).** Manager stage (`leave_requests.approve_direct_reports` + `manager_id` relationship), HR stage (`leave_requests.approve`). Approved only when both approve. Rejection needs note. No self-approval. Superadmin may decide at any stage. No manager → manager stage skipped.
- AC: requester who is the HR approver cannot approve their own request.

**FR-31 Status flow (BR-19).** pending → approved|rejected|cancelled; approved → taken|cancelled. Job moves approved → taken after end date. Cancelling approved-not-taken writes a reversal entry.

**FR-32 Ledger and entitlement (BR-18).** On 1 Jan in country timezone a grant per user and balance-affecting type from active policy, prorated by start date, rounded to 0.5. Joiners get the grant on start date. Carry-over only when policy enables it. Job is idempotent.
- AC: running the grant job twice produces one entry per user/type/year.

**FR-33 Direct day off (W-06, BR-22).** `leave_requests.create_for_others` (superadmin). Stored approved, deducts balance; may override balance with a note (BR-24).

**FR-34 Leave Calendar / My Leave.** Bank holidays and leave on one calendar; balances on My Leave.

## 7. Audit and cross-cutting

**FR-35 Audit (BR-32).** Every create/update/delete on business models writes to the activity log with actor, subject, before/after. View: `activity_logs.view` (superadmin).
- AC: a test per model asserts a row is written.

**FR-36 Money (BR-12).** All money = unsigned integer minor units + ISO 4217. No floats. Reports group by currency; no conversion.

**FR-37 Time zones (BR-34).** Store UTC; leave/holiday logic uses the employee's country timezone.

**FR-38 Expenses `[OPTIONAL]` (D-17).** `expenses.*` for hr, admin, superadmin. Lines share one currency; number `EXP-000001` generated race-safely.

## Open questions for the owner

1. May an employee see their own HR record? (D-14)
2. Should a performance review's author (non-manager admin) be able to read it back? Should HR create reviews? (D-21)
3. Are employees allowed to submit or view their own expenses, and do expenses ship in v1? (D-17)
4. When a user with role `employee` is someone's manager, who approves the manager stage? (ADR-0007)
5. Is logging on a leave day or holiday allowed, with or without warning? SPEC is silent; default allowed, no warning.
